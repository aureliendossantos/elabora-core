# D116. Free objects' frames from an origin of their own, for a page served on the web (18 Nov 2026)

A free object shows in a frame next to the course page: sandboxed without `allow-same-origin` in a package (an opaque origin), or, in a local preview, from another port of the same computer with `allow-same-origin` (`frames.ts`). A page served on the web needs a third way: its files come from a service worker, which does not serve a frame of an opaque origin, and the page and the objects must not share an origin.

Decided:
- **`FramesSource` is a port or an origin**: `{ port }` as before (pages of this computer only), or `{ origin }`: the frame loads from the same path on that origin, with `allow-same-origin`. A page tells it by `?frames=<port or origin>` (the canvas page) or `<meta name="elabora-object-frames">`.
- **An object never gets its page's origin.** A source that would give it that (the page's own port, or its own origin) leaves the frame next to the page, sandboxed as in a package.
- **An origin is `https`, or `http` on this computer, and nothing after the host** (no path, query or credentials; a trailing `/` is allowed). Any other value is ignored, as a malformed port is: a page's address is not trusted to name any site.
- **Nothing changes for a package or a local preview**: the built package carries neither, and the local preview's port works as before.

Weighed:
- **Keeping `framesPort` and adding a second parameter.** Rejected: two parameters for one decision (where the frames are) would let a page give both; one value says it once.
- **Any origin, checked by the host.** Rejected: the page is what frames the object, so it is the page that must refuse a source it should not follow.

*Revisit if:* an object needs a frame URL that differs from its page's by more than the origin.
