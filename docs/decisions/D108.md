# D108. A browser's media service: its requests, the files that come beside them, what its commands are given (19 Nov 2026)

A browser's session has no folder: a file the person picks is a `File` the window holds, and the work the desktop does with ffmpeg is the media Worker's (D106).

Decided:
- **A file comes beside the request that names it.** The window posts the request with `attachments`, the `File`s it names by their token (`{ ...request, attachments: { [token]: File } }`), and the engine's Worker gives them to `handle(message, ports, attachments)`, as `relayPort`'s port comes with its message (D105). The request carries the token where the desktop's carries a path: `importMedia`'s `path`, `importNarrationFiles`' `files`, a command's `file` (`set_narration_audio`, `add_narration_line_with_audio`) or `path` (`add_resource`). **A token without its file is a bad request, never a path read.** The desktop keeps its paths.
- **The media service is had when the host gives a media Worker** (`mediaWorker`, the engine's open message) and names `media` (D102). It answers all its requests: `importMedia` (a job, queued then running; its master kept by hash with its facts, then one change of the requester, `import_media`, source `media`), `mediaJobs`, `cancelMediaJob` (the job's work stopped; `cancelled`), `narrationPeaks` (the core's waveform on the lines' audio), `importNarrationFiles` (each file to the line its name gives, by the core's rule; finding a line by what it says needs the word aligner: those come back `unmatched` with the reason).
- **What the commands that need media are given** (D110): `lineAudio` (`set_narration_audio`: the desktop's M4A, a recording's silence cut), `recording` (`add_narration_line_with_audio`, its text given; without it, hearing it needs the transcribe service: `E_NOT_HERE`), `resourceFile` (`add_resource`: the file as it is; a PDF's own title is the desktop's, here the resource is titled as asked, else by its name), `videoOfImage` (refused with `E_MEDIA_ENCODER_MISSING`: an animated image is not encoded in a browser yet).
- **Two codes for what a browser cannot do**, on a refusal or on a failed job (`MediaJobInfo.code`): `E_MEDIA_ENCODER_MISSING` (what must be encoded, this browser cannot: AAC without an encoder, an animated image) and `E_MEDIA_NOT_DECODABLE_HERE` (what must be read, it cannot decode: HEVC outside Safari, H.264 High 10 in Firefox). A file it does not read at all is `E_MEDIA_UNREADABLE`, as at the desktop.
- **The copy gives its room the facts of what it made** (`CopyStore.mediaFacts`, D126): a master's facts are kept with its bytes (`BrowserStore.keep`) and go with the change that brings it.

*Revisit if:* the window must hand a file over before it knows which request takes it, or a browser's session must probe a file of the project it did not make.
