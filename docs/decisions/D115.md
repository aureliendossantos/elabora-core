# D115. What the canvas shows is asked of it by messages, not by scripts injected into its page (18 Nov 2026)

A host that takes pictures of the canvas and measures it (the desktop app's hidden pages: thumbnails, a screen at a moment of its timeline, a block shown before it is added, the size of a screen's texts in a language) needs to know when a render is on screen with its images, fonts and free objects ready, where a block is, how far the page runs past its window, and when a frame was drawn after a change. It did this by running scripts inside the page, which reaches the page's document and the player's API directly. A host that shows the canvas in a frame of another origin cannot: a page cannot run a script in a frame of another origin.

Decided:
- **Five questions, as messages of the canvas protocol** (`canvas-protocol.ts`, `CanvasAsks`): `shown` (the render of that id is the one shown, ready), `measure` (how far the page runs past its window, the size of each text the canvas marks), `block-preview` (a block shown in its screen, the others faded, where it is), `block-preview-clear` (the page as a thumbnail shows it again) and `mark` (a square in the page's corner, to tell a frame drawn after a change from one drawn before it). Host → canvas `{ type: 'elabora/ask', request, ask, params }`, canvas → host `{ type: 'elabora/answer', request, result | error }`. Each question names the render it is about; the canvas waits up to 3 s for that render to be shown, with its images, fonts and objects ready (as captures wait), and answers `false` or `null` when it is not.
- **Both transports carry them.** From a parent window, `postMessage`, with the page's token, from its parent only, the question checked (`canvas-asks.ts`, `askOf`): one from another window, without the token, or malformed is not answered. From the Node host, the question goes out on the event stream like a render, and the answer comes back by `POST elabora/answer?token=…` (JSON only, the page's token, 1 MB at most, local pages only, as the other routes); `host.ask(name, params)` resolves with it, rejects on a timeout (30 s: the page bounds its own waits at 3 s and 4 s by timers that a page busy starting a free object's WebGL delays by many seconds, so the host's wait is a watchdog and not the page's bound), on the host closing, or when every page it went to is gone, and with no page yet waits for the first that connects.
- **The desktop app asks through its engine process** (the page's host lives there), and its hidden pages take no injected script any more. Its captures do not change: thumbnails, block previews, miniatures and measures are the same bytes as before.

Weighed:
- **One question per script, kept for the desktop only.** Rejected: two ways to ask the same thing would drift; the message form serves both.
- **A single `measure` that does everything.** Rejected: the thumbnails wait for a render and nothing more, the previews act on the page; a question that did more than was asked would make the cheap ones slow.

*Revisit if:* a host needs a measure the five do not give; they are added here as questions, not as scripts.
