# D111. A new module's files made by the core, from a template it carries (19 Nov 2026)

A new module's files (course.json, plan.json, an intro screen, the rules for agents and .gitignore) were written by `@elabora/node` `initProject`, which read its template on the disk (`packages/node/templates/course/`) and the rules' revision from `templates/agents-revisions.json`. A browser has no such disk: a project made in a team from the browser opened with no file.

Decided:
- **The template is the core's data.** `pnpm run gen` writes `packages/core/src/project/course-template.generated.ts` from `packages/node/templates/course/`: the files a new course is made from, and the rules for agents (D34) with their revision and fingerprint. A unit test checks it is current. The template's files stay where they are, the source the generated module is made from.
- **One function makes the files**: `newCourseFiles({ id, title, language, brief })` (`@elabora/core/commands/new-course`), with the brief's checks (`checkBrief`), the starter texts and AGENTS.md as Elabora writes it (`agentsFile`, `courseNotes`). `initProject` writes what it makes, byte for byte as before. `@elabora/node` `agent-rules` reads the current rules from the core and keeps reading the older revisions on the disk.
- **Module templates (D68) stay on the computer**: a template is a whole module with its fonts, media and translations (13 MB for the eight), its translation built by `@elabora/node`. A browser that offers them will take one as a project to copy, not as data of the core.

Weighed:
- **The template fetched by the browser as files.** Rejected: two places for the same bytes, and a browser engine that cannot make a module offline. The data weighs about 4 KB compressed.

*Revisit if:* the template of a new course grows media, or a browser makes modules from the module templates.
