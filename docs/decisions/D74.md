# D74. Rebase: the value before decides; a person's value wins, an agent's gives way; whole values merge three ways first (12 Nov 2026)

A change computed on older files must be placed on the files as they are ([D73](D73.md)). Operations are absolute (a `set` says the new value, not what it changes), so a change made on a stale copy would undo what others wrote in between, without anyone knowing.

Decided:
- **The value before decides.** `rebase(head, change, since)` replays the change's operations on head and compares the value each one replaces, read from its inverse, with what head holds. The same: it applies. Different, from a person: it applies, the last written wins, and the value it replaced is reported (`overwrote`, with who wrote it when known). Different, from an agent or a file edit no Elabora tool made: it is left out and reported (`skipped`), head keeps the value. That is the rule undo already follows ([operations](../architecture/operations.md)), the other way round, and it uses the same check.
- **Whole values merge three ways first** (`mergeJson`): objects key by key, keyed arrays by id, arrays without ids position by position when their length is kept, otherwise stretch by stretch when the stretches each side changed do not overlap (two additions at one place both go in, head's first). Only the places both sides changed go through the rule above. A diff replaces an array without ids whole, and falls back to a whole document when it cannot split a change: the merge keeps what others changed beside it. A JSON file written as text merges as a value; other text files (CSS, JS) are one value.
- **Structure.** An insertion whose anchor is gone goes last. Removing an element that is gone, or moving one that is no longer where the change found it, is left out (`missing`). Removing an element changed since follows the rule of values. Inserting an id that another change took refuses the whole change (`E_SYNC_ID_TAKEN`): later operations of the change may address the element by that id, and would land in the other element.
- A change of order that only a merge would carry (a reorder inside a whole value) is not kept: moves are operations of their own.

Weighed:
- **The last written wins for everyone.** Rejected: an agent's write prepared on a stale copy would replace a person's edit; the bench shows it at once.
- **A three-way merge of text files line by line.** Not now: CSS and JS edited at once by two people are rare; a person's edit wins and the other is told.

*Revisit if:* people edit long texts at once (a merge inside a string); agents ask to be retried on their skipped operations instead of told.
