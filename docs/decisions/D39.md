# D39. The product is called Elabora (13 Oct 2026)

The product is named **Elabora** (no accent, capital E in prose; French elides it: « Réglages d'Elabora »), and elabora.studio was bought. Nothing had been published (no npm package, no tag, no release), and the testers' installs are reset by hand, so the code carries no earlier name and reads no file written under one: the existing local data was converted once, by a script outside the repositories. The git history before 13 October 2026 uses the working name.
- **Names.** Packages `@elabora/*`, the command `elabora`, the MCP server `elabora` and its tools `elabora_*`, the skills `elabora-*`, the variables `ELABORA_*`, the app's `productName` Elabora and `appId` `studio.elabora.app`, its user data `<application data>/Elabora`, archives `<course id>.elabora`, the schemas' domain `elabora.studio` (the project's own domain). The app's design system and « modules » keep their names.
- **The format starts at `elabora/0.1`**, its schemas under `https://elabora.studio/schemas/0.1/`. 0.1 because it is the first version anyone outside the project will hold, and a 0.x says the format may still change before 1.0; the earlier prototype versions were never published and nothing reads them. The chain of migrations is empty and the mechanism stays (`format/migrations/`, `elabora migrate`, the engine's `migrate` option): the next format change brings its first step, and testers' modules must then never break.
- **The SCORM manifest's identifier is `elabora-<course id>`.** LMSs compare it when a package is replaced: it never changes for a course.
- **The local data and the test runs.** `ELABORA_LOCAL_DATA_DIR` moves the local data folder: the core's suites give one to every run (`test/isolate.ts`, with the model folders, D38), and the app's launches with `ELABORA_USER_DATA` put it there too, so that no test reads or writes the author's.
- **A key the system's storage cannot decrypt** (an install's keychain entry gone, a copied user data folder) reads as no key: « Ajouter une clé… », no error.
