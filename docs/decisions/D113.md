# D113. Models in a browser: from the origin the host names, checked as they come, kept in the origin's private file system, refused where they cannot run (20 Nov 2026)

A browser's session times words (D27) and will say lines with the local voices: it needs the desktop's models (95 MB to 355 MB a file), downloaded once a browser and kept out of every course, as the desktop keeps them once a computer (D38). A browser may erase what a site keeps, a page cannot reach any host its policy does not name, and a phone has neither the memory nor the time a model takes.

Decided:
- **The same files as the desktop's, pinned by size and SHA-256 in the core** (`@elabora/core/align/models`, later the voices'), **from the models' origin the host names**: the engine's open message gives it (`models`), as `ELABORA_ALIGNER_MODELS_URL` does at the desktop, the files at the core's paths under it. The page's policy names that one origin in `connect-src`; nothing depends on the hosts a model's mirror redirects to. The tests serve the smallest model themselves, from a folder fetched once from the mirror.
- **Checked as they come.** A file is downloaded in ranged parts (16 MB), written as it comes to `<name>.part` by its synchronous handle, hashed as it is written (`@elabora/core/util/sha256`, incremental: WebCrypto hashes only a whole buffer, and 355 MB would be held in memory), then moved under its name (`move(folder, name)`, the form WebKit takes) once its size and its hash match. A stopped download resumes where its part ends (the kept part hashed again first). A file that does not match is thrown away: `E_MODEL_INTEGRITY`; an origin that does not answer, `E_MODEL_DOWNLOAD`.
- **Kept in the origin's private file system** (OPFS), `elabora-models/<id>@<version>/<file>`, by `browser/models/store.ts`, **usable with or without a session**: « Éléments téléchargés » lists, installs, removes and keeps them from the settings with no module open, and a session's requests call the same functions. A model is kept when each of its files is there at its size. A browser that keeps no files for the site (a private window) says `E_LOCAL_AI_STORAGE`.
- **Two contexts never write the same model at once**, and a model in use is never removed under it (Web Locks: `elabora-model:<id>` to write, `elabora-model-use:<id>` shared while it is used; a removal in use is `E_MODEL_IN_USE`, as at the desktop).
- **A model the browser erased is downloaded again**, with the same progress events as the first time (`alignProgress`, phase `install`), and no error: the session asks whether it is kept before each use. A file erased during a run fails that run, which is tried once more after the download.
- **Refused where it cannot run**, before anything is downloaded or read: on a phone (`navigator.userAgentData.mobile`, else the user agent), `aligners` offers none and an alignment is `E_LOCAL_AI_PLATFORM`, the desktop's code for a machine that does not run them, saying words are timed on a computer (a phone keeps them placed in proportion to the text). On a computer, a model whose peak needs more memory than the browser says it has (`navigator.deviceMemory`, Chromium alone; 8 GB for the French ones) is `E_LOCAL_AI_MEMORY`; elsewhere it is tried, and the runtime's own failure to grow its memory becomes the same code (D114).

*Revisit if:* a browser erases kept models often enough that people download them again and again, the models' origin must change per team or region, or a phone gets a model small enough to run there.
