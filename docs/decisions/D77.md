# D77. Ids a command makes end with a short random suffix (12 Nov 2026)

Ids were drawn in order: a block added without an id was `<screen>-<type>`, then `-2`, `-3`; a narration line `l1`, `l2`; a copy `<id>-copy`. Two copies of a project in the cloud ([D73](D73.md)) drew the same id for different things, and the server refused the second change whole (`E_SYNC_ID_TAKEN`, [D74](D74.md)): a person's addition lost to an accident of numbering.

Decided:
- **A readable part, then four random letters or digits**: `flow-text-k3f9`, `chemin-layer-0qzt`, `l4-m2xa` (a line's rank in its screen, then the suffix). Drawn again when the project already has the id (`freshId` in `@elabora/core` `commands/context.ts`). Ids stay 48 characters at most: the readable part is cut first.
- **One suffix per copy.** A duplicated screen or block takes one suffix for itself and everything it renames: `chemin-copy-k3f9` and its blocks `chemin-copy-k3f9-intro`, `reflexe-choix-copy-k3f9`. The copy reads as one.
- **The draw is injectable.** `CommandContext.suffix()` draws from `random` given to `commandContext` (`executeCommand`, the executor's `EditOptions.random`); by default the platform's cryptographic generator (`crypto.getRandomValues`: Node, browsers and workers alike). Tests give a seeded one, or read the ids a command returns.
- An id the caller chooses is kept as given; the server refuses it when another change took it meanwhile.

Weighed:
- **A suffix only when the copy is in the cloud.** Rejected: two behaviours to test, and a module moved to the cloud later would keep the ids that collide.
- **Longer random ids (a UUID).** Rejected: ids are read by authors and agents, in the canvas, the journal, CSS selectors; 36⁴ suffixes per readable part make a collision between two copies of one project negligible, and one would be refused, not lost in silence.

*Revisit if:* the server refuses ids taken in practice (a longer suffix).
