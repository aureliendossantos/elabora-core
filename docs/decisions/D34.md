# D34. A course's rules for agents follow the Elabora that runs; an author's edits are never overwritten (13 Oct 2026)

`elabora init` copied `AGENTS.md` once: after an update, older courses kept rules that did not know the new tools, and the « Nietzsche » session, running the app's older bundled CLI in a course whose rules came from a newer one, looked for commands that were not there. Options weighed: a versioned template that Elabora refreshes when unedited; a short, stable `AGENTS.md` that points to a command printing the current rules (always in step with the CLI that runs, but agents read their instructions file at the start and do not always run a command first, and a course read without Elabora would lose its rules); both. Originally chosen: the full rules stayed in the file, kept up to date, and the command printed those of the running CLI.
- **The file** (`@elabora/node` `agent-rules.ts`): the rules between `<!-- elabora:rules revision=<n> sha256=<16 hex> … -->` and `<!-- elabora:rules end -->`, then « Notes for this course », the author's and agents' own part, which Elabora never changes. The marker says which revision of the template the block is and a fingerprint of its text, so Elabora tells rules nobody edited from edited ones. `templates/agents-revisions.json` lists every revision of the template (27 found in the repository's history, from 5 October), appended by `npm run gen` when the template changes; an `AGENTS.md` written before the markers is recognised by its whole text (five of the six modules of the library it was tried on were unedited copies; the sixth, imported from an intermediate version, is left and reported).
- **Brought up to date without asking when unedited**, as a `system` change (`update_agent_rules`) that `elabora undo` reverts: when the app opens the course (the engine, after a format migration if any), when an MCP server starts in it, and when any `elabora` command runs in it (the note on stderr, outputs unchanged); `elabora migrate` writes them with the format. Edited rules are left as they are and said once a command runs (`elabora rules update --force` replaces them, the notes kept). An older Elabora meeting rules of a newer one (a revision it does not know) says that the commands they name may be missing and writes nothing: the opposite check.
- **`elabora rules`** prints the rules of the running CLI and where the course's stand; `elabora rules update [--force]`.
- The examples and the test courses carry the current rules (`npm run gen` rewrites theirs, a unit test checks it), so tests do not write them.
*Revisit if:* authors want to keep Elabora's rules and change one of them (a per-rule override in the notes), or the rules grow too long for agents' context (then the short file pointing to `elabora rules` becomes the better trade).

## 17 Oct 2026: progressive disclosure

Course rules outgrew their purpose as an always-read file. The marker/fingerprint/revision and author-note lifecycle is unchanged, but the **current template is a compact invariant checklist and task router**. Long recipes now live in opt-in skills and references, shipped with the CLI and exposed as MCP resources. `elabora tools skills [name [reference]]` provides the CLI-only equivalent. The authoring/design skills are short entry points; narration, translation and Storyline/Rise import are separate skills. MCP instructions point to the rules and skills rather than restating policies. Existing courses with unedited rules upgrade to the new revision; edited blocks and author notes are preserved. Old revisions remain in history.

## 19 Oct 2026: what the split dropped, restored

A review of the split found D52 still taught correctly and a few rules lost or weakened. Revision 8 gives them back in one line each, without growing the file: after a validation the agent keeps writing the plan and tells the author what changed (`elabora plan diff`); a change of substance is the author's call; no Playwright script to see a screen (`elabora look`, `elabora preview`, `elabora screenshot`); sources may hold personal data, quote only what the module needs. « The repository-root AGENTS.md governs… » is gone: an author's course folder has no repository root, and the developer's AGENTS.md already points here. Skills are also read through `elabora_docs` (D53).
