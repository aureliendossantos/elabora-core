# D110. Every command in the table, each saying what it expects from its host (19 Nov 2026)

Revises [D84](D84.md). D84 put in the core's table the commands that need nothing but the project's files, and left out « the commands that need a computer » (templates, fonts, a library's components, media, sounds): they stayed the engine's, each written again as a function of `@elabora/node` `edit/` and a line of the engine's map. A command was then said in four places (the table, Node's function, the engine's map, the protocol's types), and an engine without a disk (a browser's) could not run the rest. But most of what those commands « need a computer » for is something a host can hand over: the files of a font or of a library's component, the templates of a free object, a line's audio once made. Only the making of it (ffmpeg, a local model) belongs to a computer, and a browser has its own ways to make it.

Decided:
- **Every command is in the table** (`@elabora/core/commands/table`), by the name the journal gives it. Beside D84's commands: the plan's voice-over and sends, a line's words and kept audio, captions, an import report settled, media references after their conversion (`optimize_media`), the files of free objects, design and components, components created, forked and migrated, a theme put under its components (`upgrade_theme`), and those that need their host.
- **A command that needs more than the files says so** (`needs`): one kind of `HostNeeds` (`commands/host.ts`), each a type of what the host gives before the command runs: an object's templates, a font, a library's component, the library a component was published to, components' migration steps, a resource's file, a line's audio made from a file, a recording made a line, the text heard in a line's recording, a sound as the course keeps it, a video made from an animated image. The run takes the command's arguments and what was given (`run(context, args, given)`); bytes brought into the project come by hash (`bytes`), for the host to keep with the change.
- **The host prepares, the command writes.** A computer reads the given thing from its disk and makes media with ffmpeg and its models; a browser from what it downloaded or made with its own media and models. The arguments are what a caller asks (a file, a library, a family): the host reads them.
- **The journal keeps its names and arguments.** An entry's `journal(args, given)` says what the journal records when it is not the command as called: a file's content is in the operations (its length is journaled), a library by its id, an upgrade as `upgrade_component`, a line's audio by what was made of the file.
- **A host that cannot give what a command needs refuses it, by what it declares.** A project's room gives nothing: it runs the commands whose `needs` is null and refuses the others as commands it does not run. No second list.
- **One way to run a command on a folder.** `@elabora/node` `edit.run(dir, name, args, options)` runs any command of the table as a journaled change; what a command needs is given by this computer's provider of that kind (`edit/host.ts`), with the host's own options (its media tools, the aligner's and the transcriber's progress). The functions written by hand for each command, and the engine's map of names to them, are gone: the desktop's engine runs `edit.run`, a browser's runs `namedCommand(name).run` with `executeCommand`.
- **The types follow the table.** `CommandArgs` (what each command takes: the type of its run's arguments, checked against its schema by the compiler), `CommandResult`, `CommandNeed` and `FileCommandName` (the commands that need nothing) are read from the table: a renamed argument breaks every caller.

Left to the host, with their reason: the format migration (`migrate_format`, a course read in an older format, its schema not checked), and the course's rules for its agents (`update_agent_rules`: the files of the agents that work in a folder, which neither a browser nor a room has).

Weighed:
- **The table with the prepared arguments only** (a line's audio by hash), the host's request kept apart. Rejected: the protocol's `run` would take other arguments than the table under the same name, and its types could not be read from the table.
- **One kind of need per host** (« a computer »). Rejected: a browser gives a font's files and a library's component, not ffmpeg; each command must say which thing it expects, so that a host runs what it can.

*Revisit if:* a command needs two things of its host at once, or a host must give a command something while it runs.
