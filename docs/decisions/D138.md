# D138. « Éléments téléchargés » in a browser: the window's, with no session (26 Nov 2026)

A browser keeps the local voices' models and the word aligners in its origin's private file system ([D113](D113.md)), and a session downloads one when it first needs it. Elabora settings must list, download and remove them as at the desktop ([D38](D38.md)), with no module open.

Decided:
- **A module the window runs** (`@elabora/engine` `browser/downloads.ts`, `BrowserDownloads`): `list`, `install` (`force`: removed first), `cancel` (what the stopped download left removed, unless `preserve`), `uninstall` (the bytes freed), `storage`, `keep` and `onChange`. It needs no session and no Worker: Chromium, Firefox and WebKit write the private file system from a window. Its views are the desktop's `DownloadView` (now `@elabora/core` `downloads/types`, which `@elabora/node` re-exports), with the same ids (`voices-fr`, `aligner-en`) and the same texts; a browser has no transcriber.
- **The same folders as a session's.** A session's voices and word times read what the window downloaded, and the reverse; two contexts never write one model at once, and a model a session uses is never removed (Web Locks, `browser/models/store.ts`). A removal refused while it is used says `E_VOICE_IN_USE` or `E_ALIGN_IN_USE`, as at the desktop.
- **Another tab's state** is read from the browser's locks (`navigator.locks.query()`): a model being downloaded (`installing`, its bytes so far) or used (`inUse`). Progress and changes reach every context of the origin on one channel (`BroadcastChannel` `elabora-models`), a session's own downloads included, at most four times a second, the last always said.
- **Where nothing can be kept** (a private window of Safari): every download is listed `supported: false`, and installing one is refused with `E_LOCAL_AI_STORAGE`, the code the app words. On a phone, `supported: false` too, and the refusal is `E_LOCAL_AI_PLATFORM`.
- **Keeping the storage for good is asked by the window** (`keep`, `navigator.storage.persist`): no Worker of Chromium, Firefox or WebKit has `persist`. The browser decides, and may ask the author (Firefox does).

*Revisit if:* a browser's model is offered for a phone, a model comes in versions a browser must update in place, or the transcriber runs in a browser.
