# D112. A new module's files, the first change of an empty project (19 Nov 2026)

A project made in a team starts empty in its room: a copy that opens it (a browser's, a desktop's) has no course to show. Its first files must reach the room as any change does, so that every copy gets them and the author can undo them.

Decided:
- **A command of the table, `create_course`** (D110), that needs nothing of its host: on a project without course.json it writes the files `newCourseFiles` makes (D111) that a project reads as text, as one change, journaled, sent to the room and undone as any other. On a project that has a course.json it writes nothing (`created: false`).
- **Without .gitignore.** A folder reads `.gitignore` as bytes (`isTextPath`): written as text by a copy, a desktop's folder that read it again would find it changed and send it back as a medium. It is a folder's file for git, which `initProject` writes, not the project's.
- **Who runs it**: the copy of the person who made the project, as it opens it. The browser engine's Worker takes the course's id, title, language and brief with its opening (`newCourse`) and runs it as its first change. A desktop's copy runs it as any command.
- **Two copies at once.** A copy that opens the project after the first files reached the room writes nothing. Two copies that made them before seeing each other's (one offline) send two changes; the room places the second as any person's change over values changed since (D74): the same documents merge, the values both set differently take the last placed, and the second change reports what it overwrote. One module comes out, valid.
- **A project's room admits it as it is**: the change writes text files of a few kilobytes, adds no error, and a room runs the command itself for an editor who sends it (it needs nothing of its host).

Weighed:
- **The files written by the server when the project is made.** Rejected: the server would carry the template and the starter texts in each language, for what every copy already knows how to make.
- **A dedicated message of the sync protocol.** Rejected: a change does it, with the undo and the merge every change has.

*Revisit if:* a project is made from a module template (D68) in a browser.
