# D75. A file written by an agent's own tools is computed from the version it most likely read (12 Nov 2026)

An agent may edit a course with its own file tools: it reads a file, thinks, and writes it with its edit, sometimes minutes later. The engine turned that write into the operations between the files as they were and the file written, so the write undid, in silence, whatever the author (or, in a project in the cloud, anyone) had changed in that file meanwhile. Rebase ([D74](D74.md)) closes this between copies only if the change says what it was computed on, and here nothing tells when the agent read.

Decided:
- **The base is the closest recent version.** For each file written, among the recent versions the copy held (the files as they are first, then older ones, each with who made the change that followed it), the base is the version the written file is closest to: JSON compared by value whatever the order of keys (a program that rewrote a file in another order did not change its keys), other text by lines. The edit is the operations from that base to what was written, rebased on the files as they are as an agent's change: what changed since and the edit did not touch is kept; where both changed, what is there now is kept and the edit's operation is reported (`externalEdit` in `@elabora/core` `sync/external.ts`).
- **As close: the newest, and the person told.** When several versions are as close, the edit rewrote what changed between them, and nothing says whether the agent saw it. The newest is taken: an author who has just written a text and asks an agent to rework it gets the rework. When a person changed the file between those versions, what the edit replaces of theirs is reported as overwritten, `unsure`, and travels with the change to whoever wrote it; undoing the agent's batch gives it back.
- **An older version the write equals exactly is as close as the newest.** The program may have written back what it read long before, or put back a value that was there (a switch turned back, a title restored): nothing tells them apart, so the newest is taken and, when a person changed the file since that version, they are told, as above.
- **The agent is told.** `merged` lists the files whose content is no longer what was written, for the agent to read again.

Weighed:
- **The oldest of the versions as close.** Tried first: it kept every person's edit, but refused every agent's rework of a text a person had just changed, again on each try (the versions stay as close), so an author could not ask an agent to rework what they had just written.
- **The size of the whole-file write for text files.** Rejected: every version of a stylesheet is as far from a write of the whole file, so the oldest or newest would be taken blindly; lines tell them apart.
- **A version older than the copy keeps.** The copy keeps its recent versions (the bench, 64); an agent that writes from a file read before all of them is computed from the closest kept.

*Revisit if:* agents tell when they read (a tool that writes with the version it read would make the base exact); the engine's versions are kept for too short a time for slow agents.
