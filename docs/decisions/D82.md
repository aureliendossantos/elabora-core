# D82. Where Ajv stays, and the proof in a Worker (12 Nov 2026)

Decided:
- **Ajv is a development dependency of the repository** (`ajv`, `ajv-formats`), used by `scripts/gen-format.ts` and `scripts/reference-ajv.ts`, which the tests share. `@elabora/format` has no runtime dependency. `getAjv` is gone from its API: `validateSchema` and `compileInline` are the way in.
- **The MCP server's arguments** (`packages/cli/src/mcp/tool.ts`) are still checked by Ajv, which is a dependency of `@elabora/cli`. It runs under Node only, never in a room or a browser; the tools' schemas are the CLI's own, not the course's.
- **The proof is a bundle run in workerd.** The Worker entry loads a project snapshot, runs `loadProject` and `validateProject`, and is bundled by esbuild for workerd's conditions with no plugin; Miniflare (the version in `elabora-cloud`) runs it with no compatibility flag. Measured on 12 Nov, a laptop: the bundle is 3.6 MB (0.88 MB gzipped; the Ajv build was 2.3 MB, 0.74 MB); the first request of a module of 7 screens takes 44 to 60 ms to validate, then 6 to 10 ms; a module of 200 screens takes 202 ms the first time and 120 ms when warm. The cloud repository's room tests take this over when the room exists.

*Revisit if:* the room's cold start matters: the compiled validators are about 2 MB of source, and a Worker parses them at start.
