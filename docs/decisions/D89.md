# D89. A field or an entry of a list changed by its path; a value given whole says what it took away (12 Nov 2026)

A command that takes a list (a quiz's answers, a sort's items, a chart's rows and their anchors, a dialogue's nodes, a screen's narration) or an object (the course's navigation) replaced it whole. An agent that sent one answer to change it removed the others, often without an error: setting the navigation to free also took away `lockUntilComplete`, and a quiz with two answers left is still valid. The operations already name an entry by its id (`blocks[clicked-quiz].props.options[change]`, [D74](D74.md)), so a command can change one place and leave the rest.

Decided:
- **`set` on `update_block`, `update_screen` and `update_course`:** a list of `{ path, value }`, applied in order on the element as it is when the change is written, after the command's other arguments. The path is written as the journal writes it (`formatPath`, read back by `parsePath`): keys between dots, an entry of a keyed list by its id in brackets. It starts at the element the command changes: `props.options[b].text` on a block, `narration.lines[l2].text` or `covers[OBJ-2]` on a screen, `navigation.lockUntilComplete` or `speakers[guide].name` on the course.
- **What a value does:** it replaces what is at the path, and the objects on the way are made when missing. An entry the list does not have yet joins its end (its id is the one in brackets; in a list of strings, such as a screen's `covers`, the entry is its own value). `null` removes a key or an entry, as `null` already removes a field in these commands. An entry written again keeps its keys in their place.
- **What set refuses, with why:** a path that does not start with a field the command already changes (`props` for a block, the screen's fields, the course's settings), an element's `id` (ids are permanent: `rename`), an entry a list does not have (the message lists those it has), a list without ids (given whole, as before), the course's sections and their screens (sections given whole, or the screen commands; a section's own fields, `sections[<id>].title`, are set). A key holding dots (a theme token, `color.accent`) is the longest run of keys the object has.
- **A command's result says what its change took away:** `removed` lists the paths of the keys, entries and files its operations removed and did not write again in the same change (`course.json navigation.lockUntilComplete`, `screens/clicked.json blocks[clicked-quiz].props.options[report]`). `executeCommand` adds it to any command's result, so the MCP tools, the engine and a project's room give it unchanged. Not for a command made to remove (`destructive` in the table), nor when the result already says `removed` (the media files a command deleted) or `renamed` (a renamed id is removed and inserted again under its new one). A value given whole stays possible.
- **In the table** ([D84](D84.md)), `set` is one more property of these three commands, with one schema (`SET` of `@elabora/core/commands/set-paths`): a tool derived from the table needs no special case.

Weighed:
- **A map from path to value** (`set: { "props.options[b].text": "…" }`): shorter to write, but an order that matters (an entry added, then one of its fields) rests on the order of an object's keys, which a JSON tool may not keep. The list is the one form.
- **One command that changes any file by path**, the operations' language opened to agents: it would reach what the named commands refuse or follow (ids, a screen's blocks, the plan's validated texts) and leave out what they do (an id's references, a duplicate's translations). Rejected: set goes through the command that owns the element.
- **JSON Patch** (RFC 6902), which `write_plan` takes: its paths name entries by index, which moves when another person adds or removes one before the change is written. The plan keeps it.
- **`update_course`'s `patch`** (keys by setting, the paths in dots) stays for the app's windows, which write it key by key; it is not in the table's schema, and set does what it does for an agent.

*Revisit if:* agents need to reorder an entry (today the list is given whole, or the entry removed and added at the end); a command other than these three takes a list agents change one entry at a time (an event's actions, a layer's blocks); a list without ids that agents edit gets ids.
