# D102. A service a session does not have: not here, and which it has (19 Nov 2026)

A session's host gives it services besides the project: media jobs and the tools that read media, voices, word times, transcription, sounds, packages, the canvas, versions, printed and written documents, the agents' activity on this computer. A desktop has them all. A browser engine will have some, and others later, or never (the agents' activity of this computer). The window must tell « not here » apart from « failed » (the service exists but is offline or missing a model), so that it can show a control as off rather than an error.

Decided, the one change of the protocol for this:
- **Ten services**, named in the protocol (`Service`: `media`, `voices`, `align`, `transcribe`, `sounds`, `build`, `canvas`, `backups`, `documents`, `activity`). `@elabora/engine/base/services` lists the requests of each (`SERVICE_REQUESTS`). Every other request is the session's own: the project, its reads and changes, its history, its copy in the cloud.
- **A request of a service the session does not have** answers `not-available` with code `E_NOT_HERE`, whatever its parameters. A closed session answers `closed` first.
- **The session says which it has**: `summary.services`, so the window knows from the opening which controls to show off.
- On the desktop, `OpenOptions.services` names them, every one by default: nothing changes for the desktop app. The conformance suite runs a service's cases only against a target that has it, and checks every request of every service against a session that has none.
- `not-available` without `E_NOT_HERE` keeps its meaning: possible in this session, not now (media jobs off, no canvas open, a model not installed, ElevenLabs out of reach).

Weighed:
- **A kind of its own** (`not-here`). Rejected: an older window would not know it; with the code, it reads a `not-available` it already handles.
- **A request that lists the services.** Rejected: the summary is read at every opening already.
- **The service's name in the error.** Left out: the window knows which request it sent, and the list says the rest.

*Revisit if:* a service needs to say more than present or absent (a part of it here, a limit), or a request moves from one service to another.
