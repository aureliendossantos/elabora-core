# D80. Validation without code generation: the format's schemas compiled by `pnpm run gen`, inline schemas read by an interpreter (12 Nov 2026)

A cloud project has a room: a Cloudflare Worker (a Durable Object) that checks each change with `@elabora/core` before it numbers and broadcasts it. A Worker cannot generate code from strings: Ajv, which validated every schema, writes its validators with `new Function`, and `validateProject` failed there with `EvalError: Code generation from strings disallowed`. A browser app, later, has the same limit under a strict content security policy.

Decided:
- **One path, everywhere.** Node, a browser and a Worker run the same code; there is no export condition for workerd, and no Ajv under Node. Ajv no longer runs: it is a development dependency, used to generate and as the reference of the tests.
- **The format's own schemas are compiled when `pnpm run gen` runs.** `scripts/gen-format.ts` writes `packages/format/src/validators.generated.ts` (the 54 schemas of the registry, compiled by Ajv's standalone mode with the options the registry always had: strict, all errors, union types) and `meta-validator.generated.ts` (the 2020-12 meta-schema, which `compileInline` uses to refuse an invalid schema). Ajv's standalone code asks for three helpers by `require`; `gen` replaces them with `validator-runtime.ts` (deep equality, the length of a string in code points, format `date-time`) and stops if it finds any other `require`. The test that generated files are up to date covers them.
- **`compileInline` is an interpreter.** `packages/format/src/inline-schema.ts` walks a schema and the data and reports Ajv's errors: the same keywords, `instancePath`, `message`, `params` and order, because the core reads them (`E_SCHEMA`, `E_OBJECT_PROP_DEFAULT`, the props of a component's instance, a free object's props). It handles what courses write: the keywords listed in [D81](D81.md).
- **Ajv is the reference of the tests.** `test/unit/validation-differential.test.ts` compares the compiled validators with Ajv on the sample courses and on seeded broken copies of them, and on data made from every schema; it compares the interpreter with Ajv on the schemas a course compiles (built-in blocks and layouts, the components and objects of the samples) and on directed cases (`unevaluatedProperties` through `anyOf`, `oneOf`, `if` and `$ref`, `uniqueItems`, code points, `multipleOf` with decimals, schemas that do not compile). A few seconds by default; `ELABORA_DIFFERENTIAL=long ELABORA_SEED=<n>` runs 1500 samples per schema by hand. `test/unit/validation-no-eval.test.ts` validates the samples in a Node child started with `--disallow-code-generation-from-strings`, the V8 switch that gives a Worker's limit, and compares the findings.
- **Same findings as before.** On the 7 samples and 420 seeded broken copies of them, `validateProject` gives the same diagnostics, in the same order, as the Ajv build it replaces. Bundled for workerd (esbuild, no plugin) and run in Miniflare without the `allow_eval_during_startup` flag, the samples give the same findings; the bundle with Ajv fails there.

Weighed:
- **Ajv under Node, the compiled validators elsewhere** (the plan's « condition d'export pour workerd »). Rejected: two paths that differ in the order of an error or in a message, found in production by whoever uses the other; one path is tested by every test of the core.
- **Another validator for the registry** (a library that interprets schemas). Rejected: it would not reproduce Ajv's messages and error order, which agents read and tests pin; a generated file keeps them exactly, and a change of the format regenerates it.
- **The interpreter for the registry too.** Rejected: the registry's schemas use `$ref` across files, `unevaluatedProperties` through `if` and `oneOf`, and the 54 schemas validate every document of every project; compiled code is several times faster than a walk, and its output is Ajv's by construction.

*Revisit if:* the generated file's size matters (2 MB of source, about 0.75 MB gzipped in a Worker bundle: dropping the schemas' descriptions from the generated copy would save a tenth); a keyword of D81 is needed in a course component.
