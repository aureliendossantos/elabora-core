# D76. A command runs on files in the core: files in, its change out (12 Nov 2026)

Commands were pure already ([operations](../architecture/operations.md)), but turning their output into operations, refusing a result outside the schemas and computing the inverse lived in `@elabora/node`'s executor, next to the lock, the disk and the journal. The server of a project in the cloud ([D73](D73.md)) must run commands too (for agents in the cloud), with no disk.

Decided:
- **`executeCommand(files, name, run, options)`** in `@elabora/core` `commands/execute.ts`: runs a command on a files snapshot with its author and date, turns its output into operations (`opsBetween`: JSON compared by value, a JSON file given as text in another formatting written whole), refuses a result that breaks a schema, and returns the operations, their inverse on these files and the files after. Nothing else.
- `@elabora/node`'s executor calls it under the project lock, then checks the disk, keeps what undo needs, writes and journals; the room of a project calls it on its head.

*Revisit if:* a command needs something only a disk has (it then takes it as an argument).
