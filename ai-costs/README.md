# What paid AI services charge

The ledger behind Elabora's cost estimates (docs/decisions.md D36). Estimates are told as a share of the author's quota (D30); this ledger says what share of its list price a request is charged.

- `measurements.jsonl`: one measured request a line.
- `periods.json`: the providers, and each model and plan's price periods.
- `packages/core/src/ai/cost-ledger.generated.ts`: the periods and the averages, generated by `pnpm run gen` (never edit it). The app and the command line are shipped with it.

The rule: an average counts only in its own period, the current one, without its discount. A period with fewer than 3 measurements is told the list price. An older period's figures are never used.

## Add a measurement

ElevenLabs:

```sh
pnpm run costs:record -- --dry-run   # what the history has that the ledger lacks
pnpm run costs:record                # append it, then generate the averages
```

The tool reads `GET /v1/history`, which costs no credits, with the key in `~/.config/elabora-dev/elevenlabs-api-key`. Each item is added once, by its `history_item_id`. It also keeps what `GET /v1/models` says at that moment (`observed`). It warns when the service reports a list price or a discount that the current period lacks, or when a request's share is more than 10 % from the period's average. Either one means a new period: add it, then run `pnpm run gen`.

It is our tool, run on our accounts. The plan recorded is the account's plan at the time of the run. So record before changing plans.

For any other service, append a line by hand or with a script of your own:

```json
{"provider":"elevenlabs","model":"eleven_v4","kind":"speech","plan":"starter","date":"2026-10-13T09:29:50Z","settings":{"stability":0.5,"output_format":"pcm_24000","voices":["…"],"turns":1},"sent":{"characters":159},"billed":{"credits":64},"period":"elevenlabs/eleven_v4/starter/2026-10-13","source":{"kind":"GET /v1/history","id":"G1TQlGmXhP1L2dQu2jpx"},"observed":{"at":"2026-10-13","character_cost_multiplier":1}}
```

- `model`: the exact id the service names, snapshot included (`claude-sonnet-5-5`, `gpt-…-2026-09-30`).
- `kind`: what was asked (`speech`, `dialogue`, `chat`, `image`, `transcription`).
- `settings`: every setting sent, even ones that do not change the price today.
- `sent` and `billed`: maps of unit to count, in the units the price list and the bill use. For a language model: `{"input_tokens":…, "output_tokens":…, "cache_read_tokens":…}` and `{"usd":…}`. For images: `{"images":1}`. For a transcription: `{"seconds":…}`.
- `period`: the id of the period that holds `date`.
- `source`: where the figure comes from (a history or usage id, an invoice line, an experiment) and its id. A request is recorded once per id.
- `note`: what an experiment tested.

Then run `pnpm run gen`. It refuses a ledger with problems: a measurement in no period or in two, a period id that is not its date's, a unit with no price, a request recorded twice, or overlapping periods. `pnpm test` (`test/unit/costs.test.ts`) fails when the generated module is stale.

## Add a period

Add a period when a new model id appears, when the list price changes, or when a discount starts or ends. To do it:

1. Set the `end` of the period that stops (ISO date, excluded).
2. Add the new one in `periods.json`:

```json
{
  "id": "elevenlabs/eleven_v4/starter/2026-10-13",
  "provider": "elevenlabs", "model": "eleven_v4", "plan": "starter",
  "start": "2026-10-13T07:00:00Z", "end": null,
  "list": [{ "rates": { "characters": 1 } }],
  "discount": null,
  "source": "where the list price was read"
}
```

- `id`: `provider/model/plan/start` by convention. It never changes once measurements name it.
- `start` and `end`: `null` when the start is not known, or when the period is still running.
- `list`: the list price. `rates` gives so much of the billed unit for `per` units sent (default 1; tokens are usually priced `"per": 1000000`). Give one entry per set of settings that changes the price, with `when`: `{ "when": { "batch": true }, "rates": { … } }`, or `{ "when": { "size": "1024x1024", "quality": "high" }, "rates": { "images": 0.17 } }`. The most precise matching entry wins.
- `discount`: `{ "rate": 0.725, "announcedEnd": "…" | null, "source": "…" }`. Rate 0.725 bills 27.5 % of the list price. Set `rate` to `null` when it is not known: that period's figures are then never used. The estimate never counts on a discount. It takes the discount off the figures, and a discount still running is told at full price.
- Discounts that are not stated as a share are recorded too: credits multiplied for some plans, or a model not counted in the apps. Write them in `source` and `note` so the period still marks where the prices changed.

Then move the measurements whose dates now fall in the new period to its `id`. `pnpm run gen` names each one to move.

## Add a provider

Add it to `providers` in `periods.json`:

```json
"anthropic": { "billed": "usd", "priceSettings": ["batch"], "listMultipliers": [], "source": "https://…/pricing" }
```

- `billed`: the unit its bill uses, the key `billed` must hold in every measurement.
- `priceSettings`: the settings (or `kind`) that change what a request is charged. Each value gets its own average: batch or not, an image's size and quality, a prompt-length tier written as a setting (`"context": ">200k"`). Leave out the settings that were measured not to matter.
- `listMultipliers`: numeric settings that multiply the list price (ElevenLabs: a library voice's `voice_rate`; for a dialogue of several voices, the characters-weighted rate).

The estimate needs the service's own code to call `expectedShare` from `@elabora/core/ai/costs` with `COST_BOOK`. When it can, it should also pass the list price the service gives now (`rates`): a period whose price is no longer the service's is then not used. Give the service a `charges.json` of the author's own requests, as ElevenLabs does (`packages/node/src/voice/elevenlabs/costs.ts`).

## What the ledger holds (13 October 2026)

- 49 ElevenLabs requests of a Starter account, 12 and 13 October. Eleven v4's launch discount ran from 28 September to 13 October 07:00 UTC: 29 requests billed 0.110 of the list price, which is 0.401 without the discount. After it, 18 requests billed 0.4005.
- 5 requests bought for the ledger on 13 October (40 credits): Eleven v3 and v4 Turbo, 0.4 of the list price each.
- The share does not depend on the request kind, the voice settings, the language, the context text (not billed), the output format, timestamps, or a premade or rate-1 library voice.
