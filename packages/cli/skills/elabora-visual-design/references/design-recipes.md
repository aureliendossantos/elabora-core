# Design recipes: the order of work, the cascade, steps, backdrops and figures (on demand)

The short `elabora-visual-design` skill owns the rule: words, numbers that matter and anything scored live in blocks and props, never in CSS, templates or images. Read this reference for the exact recipes. Reference pages: `design` and `components` of Elabora's docs (`elabora_docs { page: "design" }`, or `elabora docs design --section steps` for one section; skill `elabora-components`).

## Order of work
1. **Tokens first** (`course.json` `theme.tokens`, `theme.custom`): every colour, shadow and spacing you will reuse. Custom tokens become `--t-<name>` (`color.blueprint` → `--t-color-blueprint`) in the player, layouts, free objects and generators. A material colour that only a free object uses (brass, wood, a hull) is a colour prop of the object with a literal default, not a token (skill `elabora-free-objects`).
2. **Fonts**: choose for the subject and the audience. `elabora font list` (MCP `elabora_list_fonts`) shows the vetted free fonts shipped with Elabora, there offline: serifs from EB Garamond to Merriweather, humanist, grotesque and geometric sans (Atkinson Hyperlegible Next for low vision), JetBrains Mono, display faces; each with its use, weights, size and pairings. `elabora font add . "<family>" [--for body,heading|mono|display|none] [--weights …] [--styles …] [--subsets …]` (`elabora_add_font`) copies its WOFF2 files and licence into `theme/fonts/<id>/`, declares its faces in `theme.fonts` and gives its stack to the tokens (`font.body`, `font.heading`; custom `font.mono`, which sets `code`, and `font.display`, used as `var(--t-font-display)`). When nothing in the list fits, find a font that does (npm `@fontsource/*` and `@fontsource-variable/*`: `npm pack @fontsource-variable/<id>`, then `elabora font add . --from <the .tgz>`; or WOFF2 files with `--file … --license <file>`): its licence stays next to it and travels into the package (`W_FONT_LICENSE_MISSING` otherwise); OFL and Apache allow embedding, check any other. The files hold the latin subset (Western European languages) and the latin-ext subset (Polish, Czech, Hungarian, Romanian, Turkish, Baltic…): `elabora font add` takes latin-ext when the course or one of its translations is in such a language, each file with its `unicodeRange`, loaded only by pages that use its letters; add the fonts again after adding a language, and read its notes (letters left to the next fonts of the stack). Another script: `--from` its Fontsource package with `--subsets cyrillic` (greek, vietnamese…), or its own font file.
3. **Sizes in rem.** Design at the reference window, 1600×900: 1rem = 16 px there, 14 px at 1280×720, 15 px on phones (size classes). Write font sizes, padding, margins and gaps in rem (px ÷ 16); keep borders, radii and 44 px touch targets in px. Font sizes in px are reported (`W_STYLE_FIXED_FONT_SIZE`).
4. **Layouts** for the screen types you need: screen-level components (`components/<id>/`, `"level": "screen"`) — a hero band, a figure-and-explanation split, a dark stage for 3D… Template in reading order with `data-slot` and one `data-title`; `component.json` declares the slots (`accepts`, `maxBlocks`, one `default`); `component.css` scoped with `.t-layout--<id>`, responsive with `@container (max-width: 820px)`.
5. **Stylesheet** (`theme/theme.css`, `theme.stylesheet`): style the documented hooks (`.t-screen`, `.t-block--<type>`, `.t-callout`, `.t-quiz`, `[data-slot]`…). On slides, quizzes reserve the room of their tallest feedback: `feedbackStyle: "compact"` on a quiz drops the echo of the chosen option's text (screen readers still hear it) and puts the result and the explanation in one paragraph, so two questions fit side by side. Declare **named styles** (`theme.styles.<type>`) for the looks authors may choose, and style `.t-s-<name>`. When a style would rely on a convention ("the first bold text is the figure"), make a block component with real fields instead. The theme's rules are the course's **defaults**: components come after them (`elabora.base` < `elabora.theme` < `elabora.components` < `elabora.overrides`), so a layout that needs its own value for something the theme sets on a player hook (its title size against your `.t-screen-title`, its small plate against your `.t-figure img { width: 100% }`) says it in its own `component.css`, and keeps saying it once published to a library. To override a component from the theme on purpose, put the rule, naming it (`.t-layout--hero .t-screen-title`), in a top-level `@layer overrides { … }` block of the stylesheet; better, let the component read a custom property with its default (`var(--hero-title-size, 3rem)`) that the theme sets. `elabora look` names a component rule a theme rule overrides (`W_STYLE_COMPONENT_OVERRIDDEN`) and a theme rule for a component that the component overrides (`W_STYLE_THEME_UNDER_COMPONENT`). A course without `theme.cascade` (written before 13 October 2026) still has its theme after its components (`I_THEME_CASCADE_OLD`): `elabora theme upgrade` (`elabora_upgrade_theme`) changes the order and keeps its look.
6. **The player** (D58): fit its two bars to the theme with `elabora player .` (MCP `elabora_player`), never with CSS when a token says it: `player.top.background` / `player.top.text` (a light bar with the text colour for airy themes, the primary colour for a strong identity), `player.bottom.*`, `player.accent` / `player.onAccent` for Next and Play, `player.radius` to the theme's corners (999: pills; `4` or `8` for square themes), `player.density: "compact"` for dense modules, a logo (`options: { logo: { asset: "images/<file>.svg", alt: "<organisation>" } }`; `plate: true` when `W_PLAYER_LOGO_CONTRAST` says it does not read on its bar and the charter has no version for dark backgrounds). Each bar has one `spacer` (« Espace flexible »): what is before it starts the line, what is after it ends it; move it (`move: [{ item: "spacer", bar: "top", index: 2 }]`) rather than reordering everything. Keep the default items and speeds unless the author asks (`display`, « Affichage », and `language`, for a package of every language, are off in a new module); the report lists what shows, why not, and the contrast of every pair. Look at a screen afterwards: the bars are in every look. See docs/design.md, *The player*.
7. **Screens**: set `layout`, place blocks with `slot`, pick `style`. **Scroll presentation** (`presentation.mode: "scroll"`, the default; Rise-like lessons): a screen is a page of any length; start from the built-in blocks before writing components: the layout `opening` (`"layout": "opening"`, presentations title, band, split, cover: the lesson's head with its eyebrow and reading time written by the player), `statement` for the one idea to remember, `divider` between the parts of a long page, `image` presentations (`wide`, `band`, `beside`, `over`) with a `focus`, `gallery`, `columns`, a text's `aside`, `width: "bleed"` (docs/design.md, *Bands, pictures and ornaments*); tune them with tokens and `--t-scrim`, `--t-ornament`; otherwise design a full-bleed layout with an opening band and a reading column, break reading with something to do every few paragraphs (a check, an interaction, a step), and animate with the scroll in CSS (`animation-timeline: view()` / `scroll(root)`, named view timelines with `timeline-scope` for a sticky figure that builds up), always inside `@supports` and `prefers-reduced-motion: no-preference` with the final state as the base style; a free object follows the scroll with `host.onView`. Pace a page with steps: a Continue button in the page opens the next one, or `"steps": { "3": { "opens": "answered" } }` opens the rest once the quiz above is answered (Rise-like); the bottom bar's `position: "page"` (`elabora_player { position: { bottom: "page" } }`) closes each page with Previous and Next. See docs/design.md, *Scroll pages* and *Steps*. **Slides**: think in **views**: one idea per screen, paced with `step` (Continue reveals the next step; a click in the slide can too: a click event with `{ "type": "reveal-step", "step": n }` on a marker or button, like the builds of a Storyline slide; `continueRevealsSteps: false` when only those clicks should reveal them; the learner comes back to the step reached; see docs/design.md, "Click to reveal"; for exploration in any order, style what was used with `[data-t-visited]` on buttons, tabs and disclosures, "Explore in any order"). In `presentation.mode: "slides"` a screen is one view that must fit 1600×900 with all its steps (steps keep their place); it may scroll a little at 1280×720 and reads as a page on phones. When it does not fit, split the screen (plan items are often already separate), put content side by side in slots, bound figures with `max-height` in rem, move secondary content to a layer or accordion, give a 3D object `"aspectRatio": "fill"`.
8. **Nothing moves when the learner answers.** In slides the player reserves the room of each activity's tallest feedback; budget it: compact feedback styles, short option feedback. Longer content goes into a layer with `"presentation": "panel"` (over part of the screen, the slide stays usable) or into the next step. A block shown by an event keeps its place. A component whose feedback floats over its content marks it `data-t-reserve="off"`.
9. **Backdrop** (optional, `theme.backdrop`): decoration behind every screen, never content. `layers` are elements you paint and animate in the stylesheet (`.t-backdrop-layer[data-layer="far"]`, `transform` and `opacity` only); `.t-backdrop[data-section="…"]` lets them follow the course. A 3D backdrop is a free object with `pedagogicalRole: "decoration"` (`theme.backdrop.object`). Screens pick `"backdrop": "<variant>"` or `"none"`. Text over it must keep its contrast: a panel, a dimmer variant, or a lighter text.
10. **A stage under a floating title**: when a layout floats text over a free object, declare the covered part on its slot (`--t-safe-left: 30rem`, `0` where it stacks): the object keeps its subject out of it.
11. **Figures**: draw them in `generators/<name>.mjs` from shared geometry and `tokens`, with numbered markers instead of labels; put the legend in a text block next to the figure (style `legend`). Run `elabora assets` (MCP `elabora_build_assets`); `--sheet assets.png` (`sheet: true`) shows everything they wrote on one image. A figure that draws itself as the voice speaks: `inline: true` on its image block (the SVG goes into the page, sanitized) and `elabora timing . <block> --in l2:word --effect draw --duration 2`; check it mid-way with `elabora look . --screen <id> --at l2:word+1s --motion`. Never animate inside the SVG file itself: captures and reduced motion cannot reach it.
12. **Look after every change**: `elabora look . --screen <id>` (MCP `elabora_look`) shows the screen in well under a second once warm: a look server kept for the course (one browser drawing with the GPU, no build) renders it from the files as they are, with the player's bars and its free objects, 3D included; objects your edit did not touch keep running. It writes a JPEG (in `.elabora/look/`, `--out x.png` for PNG), says whether a slide fits or how many windows a page runs, and takes `--size 1280x720,375x812`, `--state answered`, `--step <n>`, `--layer <id>`, `--viewport`, `--motion`, `--json` (where every block is). **Inspect a scroll page** with it, not with cropped screenshots: `--scroll <px|N%|block-id>` puts the window there with animations on (`--scroll 100%`: the end of the page, where an entrance must have finished); `--sheet` on a screen without a timeline shows the page down its length (0, 25, 50, 75, 100 %, or `--scroll 0,1200,world-diptych`) to see a figure build up; `--block <id>` crops the capture to one block (PNG up to 2 megapixels, else JPEG; `--scale 2` to read fine strokes and text; with `--scroll`, as it stands there). With `--scroll`, `--block` or `--motion` the look reports each block in the window (visible, clipped or outside, and how much), its animations and transitions with their timeline (time, scroll, view), range and progress, and flags **CANNOT FINISH** for a scroll-driven animation the page ends before (a `view()` range like `cover 100%` on a block near the end, a `scroll(root)` range longer than the page): its last state never shows, so give it a range it reaches (`entry`, `cover 50%`) or make its base style the final state. The first look of a session takes a few seconds (the browser starts); the server stops after 15 minutes without a look (`--stop` sooner). To watch in a browser pane (the in-app browser of your agent app included), open the page `elabora look . --url` prints: it follows your looks and every file you save. `elabora preview .` serves the whole course and reloads after each rebuild. Free objects show in both. Do not write Playwright scripts to see a screen: look, then check.
13. **Check** before you hand over: `elabora validate`; `elabora fit` (MCP `elabora_check_fit`) in seconds: which slides scroll, by how much, which blocks end below the fold, what still moves once answered (`W_SLIDE_SHIFT`), text too faint over its background (`W_TEXT_CONTRAST_MEASURED`); in scroll presentation, the length of each page and the contrast down the whole page. Motion down a scroll page while designing: `elabora look . --screen <id> --sheet`; on the built package: `elabora screenshot . --screen <id> --scroll 0,25%,50%,75%`. Screenshots of the built package, every designed screen in one run: `elabora screenshot . --screen all --size 1600x900,1280x720,375x812 --state initial,answered --out-dir shots/`; motion on a filmstrip: `--at 0,2000,4000`. `elabora test` (axe on the real CSS, overflow at phone width, fit of slides). Translated courses are fitted again: French and German run 15–30 % longer.

## Rules the validator enforces
- No text in CSS (`content: "…"`), templates or SVG figures: `W_STYLE_TEXT`, `W_COMPONENT_TEXT`, `W_ASSET_SVG_TEXT`. Numbers and symbols in figures are fine when the block next to them explains them.
- No `@import`, no external URL; `url()` to files in the course (`E_STYLE_RULE`). Hex colours outside custom properties are warnings (`W_STYLE_LITERAL_COLOR`): use `var(--t-…)`.
- Templates: no script, link, media, or button and form control without a behaviour hook; images only bound to asset props; decorative `<svg aria-hidden="true">` (`E_COMPONENT_TEMPLATE`, `W_COMPONENT_DECORATION`); slots match `component.json` (`E_COMPONENT_SLOT`).
- Styles and layouts must be declared before use (`E_UNKNOWN_REFERENCE`).
- Steps: in scroll presentation the reading order never goes back to an earlier step (`W_STEP_ORDER`); steps go on blocks of the screen, not on blocks nested in a component or a layer (`W_STEP_PLACEMENT`). Slides that overflow the reference window: `W_SLIDE_OVERFLOW`.
- Generated assets: never edit them by hand (`W_GENERATED_ASSET_EDITED`); rerun generators after changing code or tokens (`W_GENERATED_ASSET_STALE`).

## Craft notes
- Contrast is checked on the rendered page by axe: white on the blueprint band, copper only for large figures on white.
- Keep the reading order sensible on phones: the template order is the phone order.
- A style is a promise to authors: name it by its purpose ("ratio", "rule", "legend"), describe it in one line, keep it robust to any text length.
- Maths: `$…$` and `$$…$$` in any Markdown, or a `math` block; equations scroll inside their block on phones.
