# AGENTS.md — working on elabora-core

This repository is the open core of Elabora. For rules about editing a *course*, see `packages/node/templates/course/AGENTS.md` (copied into every course).

Read `docs/architecture.md` first (the packages, what each may import, the project model), then the page of `docs/architecture/` for the subsystem you change (operations and journal, media, delivery, plan, storage, import, rendering, engine). It is the contract; code that does not match it is wrong. `docs/index.md` maps the rest of the documentation; decisions are one file each, `docs/decisions/Dnn.md` (D24 is `D24.md`): read the ones the code you touch cites, not the whole log.

## Setup
- pnpm 11 (`npm install -g pnpm`; `package.json` names the version). Every checkout and every worktree runs `pnpm install` in it once: seconds, and almost no disk (pnpm clones its store). Never link a worktree's `node_modules` to another checkout's: `@elabora/*` would be that checkout's packages.
- A branch opened before pnpm (28 Oct 2026): merge `main` (a conflict on `package-lock.json`: `git rm package-lock.json`); if `node_modules` is a link, remove the link alone (`rm node_modules`, no trailing slash); then `pnpm install`. A dependency the branch added goes in again with `pnpm add`, an override or an install script in `pnpm-workspace.yaml`; commit the `pnpm-lock.yaml` that `pnpm install` changes. Never `npm install`, which would write a `package-lock.json` again.

## Map
- `packages/format/` — `@elabora/format`: normative JSON Schemas (`schemas/<version>/`), generated types, schema registry. Changing a schema changes the format: update `SPEC.md`, the validator, the compiler, a format migration and a Sampo changeset together.
- `packages/player/` — `@elabora/player`: the browser runtime bundled into every package by esbuild; keep it dependency-free. `timeline.ts` is a narrated screen's clock, segments and bar (D24); tests drive it on a virtual clock (`window.ELABORA_TEST.virtualTime`, `__elabora.timeline`). `sounds.ts` is the page's one audio context and the interface sounds (D67), their files in `packages/player/src/interface-sounds/` (`sources.json` by hand, the files written by `pnpm run sounds`). `dialogue/` is a dialogue's walk, progress, saved state and paths (D61), pure: the core imports it too; its view in the page is not (`view.ts` plays it, with its parts `box.ts`, `cast.ts`, `lines.ts`, `room.ts`, `moves.ts`; `thread.ts` is the markup).
- `packages/fonts/` — `@elabora/fonts`: the vetted fonts courses embed (`files/<id>/`: WOFF2 of the latin and latin-ext subsets and the licence), `sources.json` (kept by hand: subsets and their languages, families, Fontsource packages and versions, roles, stacks), `catalogue.json` and `README.md` written by `pnpm run fonts` (network; never edit them by hand). Only SIL OFL or Apache licences: ask the maintainers before any other. `src/index.ts` gives the catalogue as data without Node API (the desktop app imports it).
- `packages/core/` — `@elabora/core`: logic without I/O. `validate/` (every finding uses a code from `diagnostics/codes.ts`; never invent codes inline, add them to the catalogue with a fix), `components/` (registry, template engine, built-in templates in `components/builtin/`: after editing one, `pnpm run gen`), `compile/` (course data, state model, SCORM manifest, proof dossier), `project/` (files snapshot, model, loading), `i18n/`, `interop/`, `narration/` (a narrated screen's lines, the audio files of each line and whether they are up to date, its timeline and captions; docs/decisions.md D24), `dialogue/` (dialogue blocks, D61: their data for the walk, keys in the lock, the static graph, the script, `play` and `paths`, the map's layout and the client's export page; the walk itself is pure, in `@elabora/player` `dialogue/`), `import/` (Storyline and Rise modules read into one model and converted into an Elabora module with a report of every loss; docs/decisions.md D47), `lms/profiles.ts` with the LMS facts in `profiles/*.json` (sources and dates; unknown values are `null` and listed in `toMeasure`; never invent a value).
- `packages/node/` — `@elabora/node`: reading a course folder into a snapshot (`project-reader.ts`), edits run as journaled changes (`edit/`: executor, history and undo; the commands themselves are pure, in `@elabora/core` `commands/`), the project lock and journal (`journal/`), the project library and `.elabora` archives (`library/`), importing Storyline and Rise modules (`import/`: detection, a ZIP or a folder read alike, media streamed, the module written into a folder or the library), fonts for `elabora font add` (`fonts/`: vetted, Fontsource and local fonts; a reader of font tables), build and packaging (`packaging/`: streaming ZIP writer and reader), bundling, narration (`narration/`: a line's audio written with its sidecar, the build's track per narrated screen), voices (`voice/`: the voice providers, D25; `voice/pocket/` runs Kyutai's Pocket TTS with ONNX Runtime, its model downloaded once per computer; `voice/generate.ts` says a screen's lines and keeps their takes in the project's data; the voices' catalogue in `voices/pocket-tts/`, `sources.json` by hand, the rest written by `scripts/pocket-voices.ts`; `ELABORA_VOICE_TONES=1` adds test tones), generators, LMS emulator (`emulator/`, harness pages in `emulator-harness/`), free-object gates (`objects/`), preview (`preview.ts`), captures (`capture.ts`), fit and its measured contrast (`fit.ts`, `contrast.ts`), replay of an object's test (`replay.ts`), looks while designing (`look.ts`: a looker kept warm by a look server; `look-client.ts`: what `elabora look` and MCP `elabora_look` call), course and object templates (`templates/`; the course's `AGENTS.md` is the rules every course gives its agents: after changing it, `pnpm run gen` records a revision in `templates/agents-revisions.json` and gives the examples the new text, and Elabora brings courses' unedited rules up to date, docs/decisions.md D34), vendored three.js (`vendor/three-r186.js`, generated by `pnpm run vendor`; do not edit).
- `packages/engine/` — `@elabora/engine`: the editing session of the desktop app (`session.ts`: `openProject` → `Session`, one write queue, commands through `@elabora/node` `edit/` with the session's snapshot; `project-state.ts`: the project in memory and its incremental validation; `journal-tail.ts`, `disk.ts`: other writers and external edits; `render.ts`: renders; `session-canvas.ts`: the canvas host and the render cache; `session-voice.ts`: voice, alignment and transcription jobs, written through the session's queue; `session-monitor.ts`: what the watchers report and when the session reconciles it; `media.ts`; `protocol.ts`: the message protocol and its client, types only). `bench/measure.ts` measures it on a large course.
- `packages/cli/` — `@elabora/cli`: the `elabora` command line (`src/main.ts` dispatches to `src/commands/`, one module per group of the help, flags declared per command in `src/arguments.ts`), the MCP server (`src/mcp.ts`; tools in `src/mcp/`, one module per group, defined with `defineTool` in `src/mcp/tool.ts`) and the skills served to agents (`skills/`). The help and the MCP tool catalogue are recorded in `test/fixtures/`: update them with the interface.
- `bin/elabora.js` — development entry point (`node bin/elabora.js <command>`).
- `examples/` — sample courses, also used as test fixtures. `test/` — unit, e2e (Chrome) and matrix suites.

## Releases

For observable changes, add an English Sampo changeset under `.sampo/changesets/`; do not duplicate it in the generated changelog. Target `npm/elabora` and the affected packages so the root changelog describes the change. Read `docs/releases.md` and `.agents/skills/release-core/SKILL.md` when preparing a core release. In a workspace with the sibling app checkout, a request to prepare an Elabora product release uses that checkout's `.agents/skills/release-elabora/SKILL.md`; it coordinates the product notes and pins the exact core commit. Clarify only when core-only versus product scope cannot be inferred.

## Rules
1. While working, run the test files of what you change: `pnpm run test:file -- test/unit/edit.test.ts` (a few seconds; `--test-name-pattern=<words>` for one test; never `node --test` alone, which skips the isolation of `test/isolate.ts`). Before finishing a change, once: `pnpm run test:affected`, which runs `pnpm run typecheck`, `pnpm test` (the unit suite, two to five minutes as the computer is loaded), then the e2e and matrix files of the files you changed against main (`test/groups.ts`, a map kept by hand: add a new file or test to it), the changed test files and a smoke set, and says what ran, what did not and why. All must pass. A session no longer runs the whole `test:e2e`: the full regression of the core and the app runs on main once per batch (the app's `pnpm run test:batch`), and a change of shared code (the player's frame, the compiler, the format, the engine) is said to wait for it. A wait in a test is bounded for failures only (30 s), never a measure of speed. `test:affected` picks the matrix files when a change touches the player, the emulator or a sample; before a release, `pnpm run test:all` runs the three suites. The e2e and matrix files (and the app's heavy checks) share one budget for the whole computer, two at a time whichever session runs them (`scripts/heavy-slots.ts`; `ELABORA_HEAVY_SLOTS=1` for fewer): a run that waits for a slot says so and how long; never raise it to go faster on a loaded computer.
2. Never add `unload`/`beforeunload` handlers, synchronous XHR, `eval` or network access to the player.
3. Builds must stay byte-identical for identical inputs (test: `build is deterministic`).
4. After changing codes or their rules (`diagnostics/rules.ts`), profiles, block schemas, the CLI help, the agent tools or a decision: `pnpm run docs` (it writes docs/diagnostics.md, lms-profiles.md, blocks.md, cli.md, mcp-tools.md and the index docs/decisions.md).
5. TypeScript, strict, run directly by Node 24 (no build step while developing); erasable syntax only; `.ts` extensions in relative imports; packages import each other by name. format, player and core never import Node modules. No new runtime dependency without a decision (`docs/decisions/Dnn.md`).
6. Built-in templates follow the rules agents follow (test `built-in templates follow the rules agents follow`); new behaviours need hooks documented in docs/components.md and checked in `BEHAVIORS`.
7. Docs are read by people (GitHub, the site) and by agents (`elabora docs`, MCP `elabora_docs`): relative links, a new page gets its line in `docs/index.md`, and nothing a public reader cannot open (private notes, people's names, tracker numbers). The test `docs links resolve` checks links, anchors and the `docs/….md` paths and `Dn` the code names.
